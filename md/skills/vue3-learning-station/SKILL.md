# Vue 3 Learning Station — Project Convention Skill

This skill defines the mandatory workflow for adding any new learning demo or topic
to this Vue 3 training project. Follow every step in the prescribed order; skip a
step only when it is clearly not applicable (e.g., a demo with no API calls does
not need mock or api modules).

---

## Step 0: Determine Scope (required, before any other step)

Before writing any code, identify the topic name and its URL path prefix.

- **Topic name**: Short, kebab-case identifier (e.g., `pinia-demo`, `vue-use`, `form-validation`).
- **URL base**: Determine whether this is a single-page demo (`/topic-name`) or a
  multi-page module that needs a sub-directory (`/topic-name`, `/topic-name/stage1`, …).

Read the reference file `references/project-conventions.md` for the full file-tree pattern.

---

## Step 1: Create the View Component(s) (required)

Create Vue 3 files using `<script setup lang="ts">` (Composition API only, never Options API).

### Single-page demo

```
src/views/TopicName.vue
```

Use PascalCase for the file name, matching the router component name convention.

### Multi-page module (e.g., staged learning)

```
src/views/topic-name/
  ├── TopicIndex.vue       ← route: /topic-name          (overview page)
  ├── Stage1Basic.vue      ← route: /topic-name/stage1
  ├── Stage2Advanced.vue   ← route: /topic-name/stage2
  └── ...
```

Component rules:
- Use `<script setup lang="ts">` for every `.vue` file.
- Ant Design Vue components are auto-imported by `unplugin-vue-components` —
  **do NOT write `import { Button } from 'ant-design-vue'`** in `<script>`.
- Use `resolveComponent('a-tag')` inside `h()` render-functions (not direct component refs)
  because the plugin only scans `<template>`, not `<script>`.
- Command-style APIs (`message`, `Modal.confirm`, `notification`) must be imported manually:
  `import { message, Modal } from 'ant-design-vue'`.
- Type-only imports are fine: `import type { TableColumnsType } from 'ant-design-vue'`.

## Step 2: Register on HomeView.vue (required)

Open `src/views/HomeView.vue`. Inside the `demos` array (the `const` array in `<script setup>`),
add a new entry:

```ts
{
  path: '/topic-name',          // must match the router path
  title: 'Topic Display Name',  // shown on card
  desc: 'Short description (one line, summarizing what the demo covers)',
  color: '#52c41a',             // accent color (hex, pick from existing palette)
  icon: '?',                   // single emoji or short text (≤ 2 chars)
  tags: ['基础'],              // one or more of: '基础', '核心', '进阶', '实战', '库', 'Antd'
},
```

Tags reference:
| Tag | Meaning |
|-----|---------|
| `基础` | Foundational knowledge, suitable for beginners |
| `核心` | Core framework concept |
| `进阶` | Advanced topic |
| `实战` | Real-world example / CRUD |
| `库` | Third-party library |
| `Antd` | Ant Design Vue related |

## Step 3: Add Route(s) (required)

Open `src/router/index.ts`. Add a new route entry following the existing pattern.

### Single page

```ts
{
  path: '/topic-name',
  name: 'topic-name',
  component: () => import('../views/TopicName.vue'),
},
```

### Multi-page (use the existing `...routes` auto-import pattern)

```ts
// Parent
{
  path: '/topic-name',
  name: 'topic-name',
  component: () => import('../views/topic-name/TopicIndex.vue'),
},
// Child stages
{
  path: '/topic-name/stage1',
  name: 'topic-name-stage1',
  component: () => import('../views/topic-name/Stage1Basic.vue'),
},
```

Always use **lazy import** (`() => import(...)`) so Vite can code-split each demo page.
Place the new route block near related routes and keep the `...routes` spread at the end
(for auto-routes generated by `unplugin-vue-router`).

## Step 4: Set Up Mock Data (do ONLY when demo needs API calls)

Skip this step entirely if the demo does not make any HTTP request.

### 4a. Create the mock file

Create `src/mock/<topic-name>.ts`. The file must export a default array of `MockRoute` objects:

```ts
import type { MockRoute } from './types'

const routes: MockRoute[] = [
  {
    url: '/topic-name/list',
    method: 'GET',
    response: (req) => {
      // dynamic response logic
      return { code: 200, data: { list: [...], total: 10 }, message: 'ok' }
    },
  },
  {
    url: '/topic-name',
    method: 'POST',
    response: async (req) => {
      // parse body …
      return { code: 200, data: newItem, message: '创建成功' }
    },
  },
]

export default routes
```

Rules:
- Every response MUST wrap in `{ code: 200, data: …, message: 'ok' }` to match the
  project's axios interceptor expectation (`code === 0 || code === 200`).
- Use function-response for routes that need query params or dynamic data.
- Use static-response for simple dictionary/dropdown endpoints.
- Route URLs should be unique; the `matchRoute` function uses longest-prefix matching,
  so `/topic-name/list` is correctly matched before `/topic-name`.

### 4b. Register the mock file

In `src/mock/index.ts`:
1. Add a static import at the top:
   ```ts
   import topicNameRoutes from './topic-name'
   ```
2. Spread it into `allRoutes`:
   ```ts
   const allRoutes: MockRoute[] = [
     ...usersRoutes,
     ...employeesRoutes,
     ...topicNameRoutes,       // ← add here
   ]
   ```

## Step 5: Create API Module (do ONLY when demo needs API calls)

Skip if Step 4 was skipped.

### 5a. Create the API module file

Create `src/api/modules/<topic-name>.ts`:

```ts
import { get, post, put, del } from '../request'
import type { PageResult } from '../types'

// 1) Define TypeScript interfaces
export interface Item {
  id: number
  name: string
  // …
}

export interface ItemQueryParams {
  keyword?: string
  page?: number
  pageSize?: number
}

// 2) Export API functions (name starts with verb: getXxx, createXxx, etc.)
export function getItems(params: ItemQueryParams = {}) {
  return get<PageResult<Item>>('/topic-name/list', params as Record<string, any>)
}

export function createItem(data: Partial<Item>) {
  return post<Item>('/topic-name', data as Record<string, any>)
}

export function updateItem(id: number, data: Partial<Item>) {
  return put<Item>(`/topic-name/${id}`, data as Record<string, any>)
}

export function deleteItem(id: number) {
  return del<void>(`/topic-name/${id}`)
}
```

### 5b. Re-export from the API barrel

In `src/api/index.ts`, add:

```ts
export * from './modules/topic-name'
```

## Step 6: Write Documentation (required)

Create a Markdown file in the `md/` directory.

### File location

```
md/<topic-name>/<stage>.md     ← one doc per learning stage
```

Example: `md/antd/stage1-quick-start.md`

### Document structure

Every doc file must include:

```markdown
# <Stage Title>

## Learning Goals

- Goal 1
- Goal 2

## Core Concepts

Explain the key idea in plain Chinese, with short code snippets.

## API / Configuration Reference

Tables or code blocks for reference.

## Common Pitfalls

Bullet list of things to watch out for.

## Example Page

Open `/<route-path>` to see the interactive demo.
```

Keep code snippets self-contained and copy-paste ready. Use triple-backtick blocks with
`vue`, `ts`, or `bash` language tags.

## Step 7: Verify the Pipeline (required)

Run through this checklist before declaring the task done:

- [ ] `pnpm dev` starts without errors.
- [ ] The new card appears on `http://localhost:5173/` (HomeView).
- [ ] Clicking the card navigates to the new page.
- [ ] (If applicable) API calls in the page return mock data correctly.
- [ ] No `Component is not defined` or `Cannot access before initialization` errors in the console.
- [ ] `read_lints` shows zero new errors on all modified files.

## Reference: Quick File Map

| What | Where |
|------|-------|
| View component | `src/views/<TopicName>.vue` or `src/views/<topic>/` |
| HomeView card | `src/views/HomeView.vue` → `demos` array |
| Router entry | `src/router/index.ts` |
| Mock data | `src/mock/<topic>.ts` + register in `src/mock/index.ts` |
| API functions | `src/api/modules/<topic>.ts` + re-export in `src/api/index.ts` |
| Documentation | `md/<topic>/<document>.md` |
