# Stage 3：数据权限控制

## 学习目标

- 理解行级数据过滤
- 掌握字段级脱敏
- 对比前后端数据权限方案

## 行级过滤

后端在 SQL/ORM 层面加 where 条件，只返回当前用户有权查看的数据行：

```sql
-- 只能看本部门
SELECT * FROM users WHERE dept = '技术部'

-- 可以看全部
SELECT * FROM users
```

## 字段级脱敏

敏感字段在后端返回时已做脱敏处理：

| 权限 | 手机号 | 身份证 | 薪资 |
|------|--------|--------|------|
| 有 `data:user-view-sensitive` | 138****0001 | 110***1234 | - |
| 无此权限 | `****` | `****` | - |
| 有 `data:user-view-salary` | - | - | ¥15,000 |
| 无此权限 | - | - | `***` |

## 方案对比

| 方案 | 安全性 | 性能 | 推荐 |
|------|--------|------|------|
| 后端过滤+脱敏 | ⭐⭐⭐ | ⭐⭐⭐ | ✅ 生产环境 |
| 前端 v-if 过滤 | ⭐ | ⭐ | ❌ 不安全 |
| 分权限接口 | ⭐⭐⭐ | ⭐⭐ | 敏感系统 |

## 最佳实践

敏感数据始终在后端做权限校验，前端只是辅助展示。不能仅依赖前端 v-if 来保护数据安全。
